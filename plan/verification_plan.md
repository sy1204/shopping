# 프로젝트 검증 계획 (Verification Plan)

## 테스트 개요
- **목적**: 네이버 API 검색 기능이 프론트엔드와 올바르게 연동되고, 사용자가 상품을 검색하고 저장하는 핵심 시나리오(Happy Path)가 정상 작동하는지 확인
- **범위**: 백엔드 API, 프론트엔드 UI, 데이터 저장소(Supabase/Local)

## 1. 백엔드 API 테스트 (Unit & Interface)
| ID | 테스트 항목 | 기대 결과 | 비고 |
|:---:|---|---|---|
| BE-01 | `/api/search` 호출 (정상 키워드) | Status 200, `success: true`, `results` 배열 반환 | 네이버 API 연동 확인 |
| BE-02 | `/api/search` 호출 (결과 없음) | Status 200, `success: false` 또는 빈 배열 반환 | 에러 처리 확인 |
| BE-03 | `/api/products` (관심 상품 조회) | Status 200, DB 저장된 상품 목록 반환 | Supabase 연동 확인 |
| **BE-04** | **스마트 필터링 (저가/액세서리 제외)** | '맥북' 검색 시 케이스/필름 등 제외, 본 제품(90만원 이상) 노출 | 사용자 피드백 반영 |

## 2. 프론트엔드 UI 테스트 (Component)
| ID | 테스트 항목 | 기대 결과 | 비고 |
|:---:|---|---|---|
| FE-01 | 메인 대시보드 로딩 | 에러 없이 레이아웃 표시, 로딩 스피너 정상 작동 | 초기 상태 확인 |
| FE-02 | 검색어 입력 및 엔터 | 검색 API 호출 트리거, 로딩 상태 표시 | 이벤트 핸들링 확인 |
| FE-03 | 검색 결과 카드 렌더링 | 이미지, 상품명, 가격(천 단위 콤마) 정상 표시 | 데이터 바인딩 확인 |
| FE-04 | 알림(종 아이콘) 토글 | 클릭 시 색상 변경 및 로컬/DB 상태 반영 | 인터랙션 확인 |

## 3. 통합 시나리오 테스트 (E2E)
### 시나리오 A: "최저가 상품 검색 및 추적"
1. 사용자가 메인 페이지에 접속한다.
2. 검색창에 "맥북 에어 M2"를 입력하고 검색한다.
    - **Check**: 로딩바 표시 -> 결과 리스트 10개 이상 출력.
3. 가장 저렴한 가격의 상품 카드를 확인한다.
    - **Check**: 쿠팡/네이버 등 몰 이름과 가격이 일치하는지 육안 확인.
    - **New Check**: 1~2만원대 케이스, 필름 등이 상단에 보이지 않아야 함.
4. 해당 상품의 '종 아이콘(알림)'을 클릭한다.
    - **Check**: '관심 상품에 추가되었습니다' 토스트 메시지 출력.
5. 페이지를 새로고침한다.
    - **Check**: '나의 관심 상품' 섹션에 방금 추가한 상품이 유지되어 있어야 함.
